# 寫作規則摘要與來源

本文件改寫原始專案的規則摘要。
本文件不是官方標準全文，也不包含官方字典。
英文規則取材自 ASD-STE100 Issue 9。
該版本於 2025 年 1 月發布。

## 標準範圍

ASD-STE100 是為技術文件設計的受控英文。
標準包含九類、共五十三項寫作規則。
官方字典約收錄九百個核准詞。
字典另列約一千二百個不建議詞與替代用詞。
各核准詞限定詞義與詞性。
專案可以另外定義技術名詞與技術動詞。

官方標準只規範英文，不定義中文合規方式。
中文的三十字目標是本技能的改編建議。

## 九類規則

| 類別 | 英文規則摘要 | 中文改編方式 |
|---|---|---|
| 用詞 | 依核准詞義與詞性使用詞彙 | 同一概念固定名稱，避免同義詞混用。 |
| 名詞 | 控制名詞群組長度 | 拆開堆疊名詞，明確寫出關係。 |
| 動詞 | 使用核准動詞與允許的動詞形式 | 直接寫動作，不用冗長的名詞化表達。 |
| 句子 | 一句一個指令，限制長度 | 一句一事，保留必要主詞與條件。 |
| 程序 | 清楚列出操作順序 | 步驟使用編號，一步一動作。 |
| 說明 | 清楚組織說明文字 | 一段一個主題，最多六句。 |
| 安全 | 明確表達安全指令 | 先寫危險與條件，再列出對應操作。 |
| 標點與詞數 | 不使用分號，依規則計算英文詞數 | 不用分號連接句子，不把中文字數當英文詞數。 |
| 寫作實務 | 避免片語動詞等歧義來源 | 不用成語、俚語與含糊指代。 |

此表只摘要類別，不列出五十三項規則全文。
正式用途必須查閱官方文件。

## 可直接檢查的結構

- 指令與程序每句最多二十個英文單字。
- 說明文字每句最多二十五個英文單字。
- 英文名詞群組最多三個詞。
- 一段只寫一個主題，最多六句。
- 不使用分號。
- 指令使用主動語態。
- 說明中的執行者不明或不重要時，可以使用被動語態。

英文優先使用不定詞、祈使句與簡單時態。
過去分詞可以作形容詞。
不要只為符合時態規則而刪除必要資訊。
例如 `may have failed` 表示對過去事件的推測。
改成 `failed` 會將推測變成事實。
必須保留推測，並註明偏離時態規則。

## 需要官方字典的詞彙檢查

未取得官方字典時，只能檢查文件內的用詞一致性。
不能證明某個英文詞符合核准詞義與詞性。
嚴格模式也不能取代這項檢查。

本技能不重製官方字典。
免費取得標準不代表可以任意散布標準。
必須依官方授權條件使用官方文件。
來源專案的 MIT 授權不涵蓋官方標準本身。

## 中文改寫的優先順序

1. 保留原文事實。
2. 保留否定、條件與適用範圍。
3. 保留可能性與義務強度。
4. 消除指代與句法歧義。
5. 縮短文字。

不要將「建議」改成「必須」。
不要將「有時」改成「通常」。
不要將設計目標改成實測結果。
不要將「未回報錯誤」改成「已證明成功」。

## 檢查器限制

來源專案提供英文結構檢查器 `ste-lint.py`。
本中文改編沒有複製該程式。
英文檢查器不能驗證中文句法或語意一致性。
任何零違規結果都不等於正式合規或語意正確。
